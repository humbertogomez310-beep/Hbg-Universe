UNIVERSO HBG + HBG CORE

PROMPT MAESTRO DE DESARROLLO Y FINALIZACIÓN DEL ECOSISTEMA

---

1. MISIÓN PRINCIPAL

El objetivo es terminar y consolidar dos elementos fundamentales del ecosistema:

UNIVERSO HBG

y

HBG CORE

IMPORTANTE:

UNIVERSO HBG y HBG CORE NO son exactamente lo mismo.

UNIVERSO HBG es la aplicación, experiencia e interfaz central del ecosistema.

HBG CORE es el núcleo tecnológico que permite conectar, coordinar y compartir información entre las aplicaciones HBG.

La arquitectura final debe permitir que cada aplicación funcione de forma independiente, pero que todas puedan unirse dentro de un ecosistema común.

---

2. VISIÓN FINAL

El ecosistema HBG debe evolucionar hacia:

                UNIVERSO HBG
                     │
                  HBG CORE
                     │
    ┌────────────────┼────────────────┐
    │                │                │
 INSTINTO         VIBRA PRO      TERMINADOR IA
    │                │                │
    └────────────────┼────────────────┘
                     │
              FUTURAS APPS HBG

HBG CORE es el núcleo.

UNIVERSO HBG es la puerta principal y experiencia central.

Las demás aplicaciones son módulos/productos independientes del ecosistema.

---

3. REGLA FUNDAMENTAL

NO convertir todas las aplicaciones en una sola aplicación gigante.

Cada producto debe mantener:

- su propia interfaz
- sus propios componentes
- sus propias funciones
- su propia lógica específica
- su propia identidad

Pero debe existir una capa común que permita:

- identidad HBG
- comunicación
- navegación entre productos
- intercambio de información permitida
- preferencias compartidas
- estado del ecosistema
- servicios comunes
- futura inteligencia centralizada

Esa capa es:

HBG CORE

---

4. OBJETIVO DE HBG CORE

HBG CORE debe funcionar como el sistema operativo lógico del Universo HBG.

Debe ser responsable de coordinar, cuando corresponda:

- identidad del usuario
- perfil HBG
- ADN Digital
- preferencias
- memoria
- comunicación entre aplicaciones
- eventos del ecosistema
- conexión entre productos
- configuración global
- estado de servicios
- capacidades compartidas
- futuras funciones de IA
- descubrimiento de aplicaciones
- actividad del ecosistema
- integración con TERMINADOR IA

HBG CORE NO debe convertirse en una interfaz gigante.

Debe ser principalmente una capa central de servicios, estado, contratos y comunicación.

---

5. HBG CORE COMO FUENTE CENTRAL

Cuando un dato sea realmente global para el ecosistema, HBG CORE debe ser la fuente de verdad.

Ejemplos:

- identidad HBG
- perfil
- configuración global
- preferencias compartidas
- aplicaciones conectadas
- capacidades disponibles
- eventos globales
- memoria global permitida

Pero NO mover automáticamente toda la información específica de cada aplicación a HBG CORE.

Ejemplo:

VIBRA PRO debe seguir siendo responsable de su biblioteca musical.

INSTINTO debe seguir siendo responsable de sus propios datos.

TERMINADOR IA debe seguir siendo responsable de sus funciones.

HBG CORE solamente debe almacenar/coordinar aquello que realmente sea transversal.

---

6. UNIVERSO HBG — IDENTIDAD

UNIVERSO HBG debe sentirse como el centro del ecosistema.

No debe parecer simplemente otra landing page.

Debe sentirse como:

"Este es el lugar donde vive todo HBG."

La experiencia debe combinar:

- tecnología
- música
- inteligencia artificial
- identidad digital
- creatividad
- proyectos
- aplicaciones
- evolución personal
- universo visual HBG

10. APLICACIONES HBG

Como mínimo:

INSTINTO

VIBRA PRO

Plataforma musical conectada a HBG CORE.

TERMINADOR IA

Sistema de inteligencia artificial del ecosistema.

UNIVERSO HBG

Centro del ecosistema.

- abrir aplicación
- conocer su función
- ver estado de conexión
- ver si está activa
- navegar entre aplicaciones

NO duplicar las aplicaciones dentro de UNIVERSO HBG.

UNIVERSO HBG solamente debe funcionar como centro y portal.

---

11. TERMINADOR IA

TERMINADOR IA debe tratarse como una aplicación independiente pero profundamente integrada con HBG CORE.

Debe poder funcionar como:

- asistente
- agente inteligente
- interfaz de IA del ecosistema
- sistema de automatización futuro
- acceso inteligente a servicios HBG

UNIVERSO HBG debe tener un acceso claro a TERMINADOR IA.

HBG CORE debe ser capaz de servir como puente entre TERMINADOR IA y las demás aplicaciones cuando corresponda.

NO crear una segunda IA dentro de HBG CORE.

HBG CORE coordina.

TERMINADOR IA ejecuta la experiencia inteligente.

---

12. ADN DIGITAL HBG

Crear una sección conceptual llamada:

ADN DIGITAL

Debe representar la identidad digital del ecosistema.

Puede contener:

- perfil
- preferencias
- actividad
- aplicaciones utilizadas
- intereses
- configuración
- historial relevante
- memoria autorizada
- evolución dentro del ecosistema

IMPORTANTE:

Diseñarlo de forma modular.

No asumir que todos los datos deben almacenarse desde el primer día.

Construir la arquitectura para poder ampliar el sistema posteriormente.

---

13. PERFIL HBG

Crear un perfil central.

Debe permitir gestionar:

- nombre
- avatar
- identidad HBG
- preferencias
- configuración
- aplicaciones conectadas
- privacidad
- memoria
- personalización

---

14. MEMORIA HBG

Crear una arquitectura de memoria global.

Debe diferenciar entre:

Memoria global

Información que puede ser utilizada por distintas aplicaciones.

Memoria específica

Información perteneciente únicamente a una aplicación.

Ejemplo:

Una preferencia general puede ser global.

Una playlist de VIBRA PRO debe permanecer dentro de VIBRA PRO.

NO mezclar ambos niveles.

---

15. EVENT BUS / COMUNICACIÓN

HBG CORE debe tener una arquitectura preparada para eventos.

Ejemplos:

- APP_CONNECTED
- APP_DISCONNECTED
- USER_UPDATED
- PROFILE_UPDATED
- MUSIC_PLAYED
- FAVORITE_ADDED
- FAVORITE_REMOVED
- AI_ACTION
- MEMORY_UPDATED
- SETTINGS_UPDATED

Los nombres pueden adaptarse a la arquitectura existente.

La finalidad es permitir que las aplicaciones reaccionen a acontecimientos del ecosistema sin crear dependencias directas innecesarias.

---

16. SISTEMA DE APLICACIONES CONECTADAS

HBG CORE debe poder registrar aplicaciones.

Cada aplicación debe tener información como:

- id
- nombre
- versión
- estado
- capacidades
- fecha de conexión
- última actividad
- permisos

Ejemplo conceptual:

INSTINTO
status: connected

VIBRA PRO
status: connected

TERMINADOR IA
status: connected

UNIVERSO HBG
status: core-interface

Esto debe basarse en el código existente, no crear una implementación paralela si ya existe.

---

17. CONTRATOS

Todo intercambio entre aplicaciones debe realizarse mediante contratos claros.

Evitar que:

INSTINTO → dependa directamente de componentes internos de VIBRA

o:

VIBRA → dependa directamente de componentes internos de TERMINADOR

La comunicación debe pasar por interfaces/contratos definidos por HBG CORE.

Esto permitirá agregar futuras aplicaciones sin romper las existentes.

19. SEGURIDAD Y PERMISOS

Preparar un sistema de permisos.

No todas las aplicaciones deben tener acceso a toda la información.

Ejemplos:

- leer perfil
- escribir perfil
- leer preferencias
- leer memoria
- escribir memoria
- acceder a eventos
- ejecutar acciones
- acceder a capacidades

Los permisos deben ser explícitos.

No implementar acceso global indiscriminado.

---

20. OFFLINE / RESILIENCIA

HBG CORE debe diseñarse para que una aplicación pueda seguir funcionando aunque otra no esté disponible.

Ejemplo:

Si TERMINADOR IA no está disponible:

VIBRA PRO debe seguir funcionando.

Si VIBRA PRO está cerrada:

INSTINTO debe seguir funcionando.

Si internet desaparece:

las funciones locales deben continuar cuando sea posible.

La arquitectura debe evitar que una aplicación caída derribe todo el ecosistema.

36. CRITERIO DE "TERMINADO"

UNIVERSO HBG estará terminado cuando:

- tenga Home funcional
- tenga dashboard
- tenga identidad HBG
- tenga Perfil
- tenga ADN Digital
- tenga HBG CORE visible y funcional
- muestre aplicaciones conectadas
- tenga navegación entre aplicaciones
- tenga acceso a TERMINADOR IA
- tenga arquitectura de memoria
- tenga sistema de eventos
- tenga contratos
- tenga permisos básicos
- tenga PWA
- sea responsive
- tenga buena UX
- no existan sistemas duplicados
- las conexiones existentes estén verificadas
- el build sea estable

HBG CORE estará terminado cuando:

- pueda identificar aplicaciones
- pueda registrar conexiones
- pueda exponer servicios globales
- pueda manejar identidad
- pueda manejar preferencias globales
- pueda manejar memoria global
- pueda manejar eventos
- pueda manejar permisos
- pueda funcionar mediante contratos
- pueda sobrevivir a la desconexión de una aplicación
- pueda incorporar futuras aplicaciones
- esté conectado correctamente con INSTINTO
- esté conectado correctamente con VIBRA PRO
- esté conectado correctamente con TERMINADOR IA
- esté conectado correctamente con UNIVERSO HBG
